## Operations

- Workflow: `.github/workflows/nightly-qa.yml`, **Nightly offline QA**.
- Schedule: `30 17 * * *` UTC = daily 02:30 JST on the following date. GitHub scheduled runs may start late; they use the default branch. While this change remains a Draft PR, nightly scheduling is not active. This task does not merge or modify main.
- Once an authorized maintainer has integrated the workflow, use Actions → Nightly offline QA → Run workflow → choose the branch → Run workflow. CLI equivalent: `gh workflow run nightly-qa.yml --repo celticmusic-nagoya/the-windbound-oath --ref <branch>`.
- Local run (Python 3.12 and Node 22 recommended): `python3 tools/qa/run_nightly.py --out /tmp/windbound-nightly-qa`. Exit 1 means one or more checks failed; other checks still execute. No automatic repair or retry occurs.
- Download `nightly-qa-<run_id>-<run_attempt>` from the run's Artifacts. It contains per-check logs, `results.json`, `report.md`, and `workflow-steps.json`. The report also appears in the job summary. Setup failures get a fallback report pointing to Actions logs. Artifact retention is 7 days.
- Failure excerpts identify observed assertions/errors/timeouts and their logs, without AI analysis. Existing failures also make the job fail; no allow-failure baseline is introduced.
- Suite budget: 300 seconds; each command: 20 seconds; job: 8 minutes. Budget exhaustion fails outstanding checks. Concurrency serializes runs on the same ref. Forced runner termination/job cancellation may prevent the final upload; inspect Actions logs in that case.
- Workflow token has only `contents: read`; checkout does not persist credentials. No secrets, AI API calls, deployment, push, issue/comment creation or paid-service credentials are used. Artifact upload uses GitHub's built-in Actions runtime authentication. Actions/storage usage remains subject to the repository's GitHub allowance; this adds no AI API charges.

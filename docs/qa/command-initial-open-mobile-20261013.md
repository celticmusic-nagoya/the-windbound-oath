## タップ領域 (44px基準)

展開中ボタンの名目幅/高さは全条件44px以上。ただし初期表示でpanel/viewportに切られるボタンがある。

| 画面/戦闘 | 44px未満の初期可視領域 |
|---|---|
| portrait/normal | なし |
| portrait/raider | なし |
| landscape/normal | normalCommandClose (310.0×35.4px), nItem (310.0×31.4px) |
| landscape/raider | rbItem (310.0×30.8px), rbWind (310.0×0.0px) |
| small/normal | nItem (155.0×16.6px) |
| small/raider | rbItem (155.0×0.0px), rbWind (155.0×0.0px) |

折りたたみ時のCOMMANDは縦/小型108×34px、横112×34px。高さ34pxは44px基準に不足するため、推奨案でも当たり領域を44px以上にする必要がある（未適用）。展開の初期表示でアイテム/風の一閃が切れていることは示したが、スクロール後の全項目到達を確認した測定ではない。

再現: 上記画面寸法をモバイルemulationに設定、通常戦闘/DEVレイダーに入る→COMMANDをtap→末尾/味方を比較。 [画像と生データ](command-initial-open-mobile-20261013/) に各条件の開閉を保存。現在のDEV一撃撃破ボタンも実際のレイアウトに含める。DEV非表示の製品版やFionaターンの別コマンド数は未測定。

## 3案

| 案 | 利点 | 欠点/必要条件 | 判断 |
|---|---|---|---|
| 全スマホで展開 | 追加タップが不要、行動が見つけやすい | 味方の動き/姿を覆う。横/小型で末尾が切れる | 現状レイアウトでの初期採用は非推奨 |
| 折りたたみ+常設ボタン | 初期の戦場を広く見られ、縦横で操作が同じ | 毎回1タップ必要。現ボタン34pxを44px以上へ、COMMANDの分かりやすさをQA | **推奨** |
| 縦は展開・横は折りたたみ | 横の狭さに対処しつつ縦の発見性を確保 | 縦レイダーでも味方ほぼ100%に重なる。回転で挙動が変わる | 次点、縦battle配置の別改善が必要 |

数値はPC Chromium参考値、Android実機は未測定。向きによる自動切替を実装・動作検証したものではない。基本操作変更の採用はユーザー判断。

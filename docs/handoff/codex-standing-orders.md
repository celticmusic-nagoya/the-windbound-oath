# Codex 常設指示書(2026-10-13〜)

作業開始前に必ず `AGENTS.md` と本書を読むこと。ユーザーは **Codexへの作業指示を全面的に事前承認** している。指示のたびに許可を求めず、範囲内なら進めてよい。

## 1. 事前承認の範囲と限界
承認済み: 調査・分析・提案書、アセット仕様書/生成指示文、テスト追加・実行、`work/codex-*` ブランチでの実装・コミット・push、ドキュメント更新。
承認外(必ず止めて報告): main への直接コミット(PR経由のマージは `AI_HANDOFF_PROTOCOL.md` §5-6 の条件を満たす範囲で事前承認済み。直接pushは `COLLABORATION.md` §1/§6 が既に許す範囲のみで、拡大解釈しない)、force push、セーブ構造の非加算的変更、**未決定の戦闘数値の確定**(風の舞など。提案のみ)、採用済みアセットの差し替え、Android実機性能未検証での高さ機能のメインマップ有効化、大規模マップ再レイアウト、破壊的操作(履歴書き換え・ブランチ削除)。
判断に迷う場合は、安全側(提案書化・DEV限定・フラグOFF)で進め、報告に「要判断」と明記する。

## 2. ブランチ・コミット規約
- 作業は `work/codex-<topic>` ブランチ。main へのマージは、`AI_HANDOFF_PROTOCOL.md` §5-6 の条件(正典・確定仕様の不変、実装者本人以外の独立QA PASS、直前のHEAD・差分・競合確認、事後報告)を満たす場合に Claude または Codex が行ってよい(rollback ref確保後 `--no-ff` 等の祖先を保つマージ)。QAがCONDITIONALの場合はPASS扱いにせず、条件の解消と再確認を行う。FAILのPRはマージしない（Protocol §5-6）。
- コミット末尾: `Co-Authored-By: Codex <noreply@openai.com>` (Claude作業分とは区別する)。
- 小さくこまめにコミットし、各区切りで必ず push(セッションが止まっても成果が残るように)。

## 3. テスト規約
- 変更前後で関連テストを実行し、結果を比較する。静的サーバはテストごとに自前で起動・停止し、**テストは直列実行**(並列は偽失敗を生む)。
- 一部テストは失敗しても exit 0 を返す。必ず出力の `^FAIL ` / `^FAILS [1-9]` を grep して判定する。
- 既知のmain既存失敗: `m13_elder_attack_text`, `m4_e2e`(古い台詞期待値)。それ以外の失敗は新規リグレッションとして扱う。
- 結果は「合格 / 失敗 / 未実施 / main既存 / 新規」に分類して報告。
- モバイル縦(390×844)・横(844×390)でクリップが無いことを確認(UI変更時)。

## 4. 報告形式(成果物ごと)
1. 要約(3行以内) 2. 変更ファイル 3. テスト結果(上記分類) 4. 未決事項・要判断 5. ブランチ名とコミットhash 6. 次の提案。
詳細は `docs/handoff/` または `docs/qa/` に置き、チャット報告は簡潔に。

## 5. 利用制限・中断時の取り決め
- 利用制限などで止まった場合は **ユーザーが Claude に報告する**。Codexは止まる直前に自力で次を行うこと:
  - 作業中の変更を WIP コミットして push(`wip:` 接頭辞)。
  - `docs/handoff/codex-status.md` に「完了/進行中/未着手」「再開手順」「未コミットの懸念」を追記。
- 再開時はまず `codex-status.md` と最新の `git log` を読み、重複作業を避ける。
- Claudeは「Codexに依頼済み」を完了とみなさない。Codexの成果は納品報告+ブランチ確認後に統合する。

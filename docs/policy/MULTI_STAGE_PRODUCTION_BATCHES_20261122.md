# Multi-stage production batches — director approved 2026-11-22
Mandatory for all AI agents, automations and character/world production. Extends Production OS, continuous authoring, blueprint-first and causal retry v3; no asset adoption or future main merge implied.

## Execution units
- Character phase 1: face, hair, body in one native session where supported; phase 2: wardrobe and equipment in one session. Rig/deformation and runtime integration follow applicable gates. Morwen VRoid-first and qualified HairHarpy sequence remain binding.
- Map/environment phase 1: terrain/rock/architecture and physical interfaces, road/bridge/water geometry, placement in asset-local coordinates as appropriate; phase 2: materials/UV, vegetation/props, lighting/composition and scene preview; phase 3: collision/traversal, optimization, integration and regression. Combine adjacent phases when ownership, readiness and budget allow. Village/cliff/meadow/forest and independent modules may run concurrently; never combine conflicting owners into one writer.
- Phase boundaries are checkpoints, not mandatory job boundaries. Prefer one startup/session per meaningful milestone; reuse runtime and verified artifacts. 60–120 minutes is an initial planning heuristic, never a required stop. For verified standard GitHub-hosted public-repository runners, extend productive sessions as needed within the provider's actual job limit (currently plan at most six hours, reserving checkpoint/upload time); verify runner type, billing and effective timeout before dispatch. Avoid per-control/per-object dispatch, fixed idle waits, and report-only stops.

## Execution contract
Before dispatch, verify main policies, existing owner/lease, input hashes, module blueprints, dependency DAG, qualified tools and exact-byte preflight. Record ordered stages with commands/operations, expected outputs, acceptance checks, time budgets, dependencies and checkpoint paths. Never claim an unimplemented GUI operation is executable. Use bounded, tested operations. Within the same session author, preview, measure, correct, save unique editable checkpoints, hash and reopen; record actual evidence. Preserve previous verified inputs. Skip only stages whose exact input/runtime/settings/QA and output hashes are verified. On failure isolate affected dependents, continue independent safe stages; causal retry v3 applies. Stop at time/permission/canon/safety limits with precise resume pointer. Do not promote partial outputs as completed phase. Final matched views and independent G1–G4 remain separate; no automatic adoption/publication/main merge or added cost.
Implementation state: policy approved; individual workflow adapters and actual multi-stage runtime verification required. Existing workflows must be migrated incrementally on their owning PRs, not duplicated or replaced while running.

## Mandatory executable blueprint and full-deliverable closure — director approved 2026-11-22
Applies to every AI, automation and workstream (character, world, environment, UI, code, combat, VFX, animation and integration). This section strengthens the existing Production OS; it does not authorize canon changes, paid resources, premature method switches or asset adoption.

1. Before precision authoring, audit current main, owner/lease, canonical sources, prior failures, dependencies and actual deliverable. Build or improve the existing complete target blueprint, not a description of the current model. Inventory every required operation, reference, prerequisite, preflight, acceptance test, tool capability, missing information and resolution task. Persist source hashes, provenance, license, units, axes, scale, projection/camera, target values, tolerances, measurement method, uncertainty and dependencies; distinguish measured, inferred, provisional and unknown. Record unavailable information with evidence, owner, executable resolution and affected stages; never invent hidden geometry or block independent modules unnecessarily. A complete inventory can contain explicit gaps; readiness is evaluated per module.
2. Character blueprint covers face/eyes, anatomy/body, asymmetric hair guides and volume, wardrobe layers/seams/UV/materials, equipment attachment and clearance, topology, rig/deformation and runtime. World covers plan/elevations/sections, rock/terrain, architecture, ground contact, water, roads/bridges, vegetation, materials, collision/traversal and performance. UI/code/other modules cover states, interfaces, data, behavior, error paths, accessibility/device and regression acceptance as applicable.
3. Machine-readable execution contract: every required target has a stable ID, evidence reference, target/range/tolerance, measurable observable, qualified operation or explicit missing capability, dependency IDs, preflight, expected postcondition, checkpoint and QA. Link annotated diagrams to the same IDs. At launch load and validate the actual blueprint bytes and record SHA; reject stale or absent targets for affected precision edits. Do not substitute hardcoded trial values for targets. Calibrate native control response on disposable copies with actual projections; map target error to bounded control changes, measure before/after using matched camera/scale and record residuals. If automation cannot measure a target, use qualified human/AI review of actual evidence or mark it blocked; no fabricated geometry/pass. Reuse verified mapping and update only affected design data. Design completion, runtime wiring, actual edit and QA are distinct milestones.
4. Execute a delivery-sized dependency batch, not one operation: character face, body, hair, wardrobe and equipment in the same native session where supported, and all ready downstream steps; world coherent area and its interfaces/materials/placement/traversal; other workstreams similarly end-to-end. Optimize for maximum faithful reproduction within the verified actual free runner limit, at most 360 minutes per standard job including reserved save/reopen/upload time. No mandatory six-hour wait, no artificial keepalive, no unapproved cost. Continue author-preview-measure-correct-save-reopen loop through every ready module, then final matched views, technical tests and independent QA. Do not stop for routine progress reports, successful individual control tests or arbitrary phase divisions. Only real approval, safety, unresolved prerequisites, tool limits, causal retry budget or effective deadline justify a scoped stop. Finish remaining ready independent stages safely, persist exact resume pointer and automatically resume remaining work when qualified and authorized without repeating verified stages.
5. Before each dispatch run exact-byte syntax/schema/semantic tests and dependency/input checks; verify free runner and timeout, owner and active/queued jobs. Use verified automatic event triggers or authorized existing dispatch, prove actual run ID and deduplicate by input fingerprint and lease. On error classify root cause with logs/screens and actual artifacts, preserve last verified immutable native checkpoint, recover in-session with evidence-backed alternatives and postconditions; quarantine ambiguous edits. Causal Retry v3 governs repeated causes. Fix recoverable defects, preflight changed bytes and resume; never blindly rerun unchanged failure. Store failure, hypothesis, changed operation, expected result, actual result, time budget and next operation. If automatic launch/recovery is unqualified or unavailable, report precise unblock conditions, do not claim it works.
6. Closure: compare actual editable output to all applicable blueprint targets, record target/actual/residual/tolerance and PASS/FAIL/BLOCKED/NOT_RUN, matched multi-view evidence, native reopen/hash, scope and remaining gaps. Require actual model/scene/program behavior, not JSON/CI or screenshots alone. G1–G4 and explicit adoption remain mandatory. A partial candidate is not a complete deliverable. Report meaningful evidence, not paperwork. Existing owners #427 and #421 and all other owners migrate adapters on their own PRs, respecting leases. Policy approved; executable blueprint binding, full-session runtime and automatic recovery remain unqualified until independently demonstrated.

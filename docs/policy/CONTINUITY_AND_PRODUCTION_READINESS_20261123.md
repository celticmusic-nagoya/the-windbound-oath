## Mandatory synchronization
At startup and before any mutation, dispatch, QA instruction or recovery, reconcile current main policy, owner acknowledgement, task/stage, lease/fencing token, branch/HEAD, all-event Actions (pagination and errors checked), actual candidate and source/output SHA, artifact expiry/access, gates and next operation. HEAD alone is not progress. A snapshot, chat summary, PR comment or prior success is not a live owner state. If incomplete or contradictory, label SYNC_UNVERIFIED, prohibit affected writes/dispatch/recovery and unsolicited old-candidate QA; request only missing evidence from owner. Independent ready work continues. No rewind of stages without explicit causal evidence and owner agreement. Historical QA is candidate-specific and cannot invalidate newer candidates by implication. Do not claim agents received or executed instructions without acknowledgement.

Use existing PRs and Production OS queue; owner records material progress and handoff with monotonically ordered revision, timestamp, task ID, scope, lease, HEAD, run/event/artifact IDs, hashes, gates, blockers, next action and dependencies. Reject stale or mismatched updates, preserve evidence, never rewrite history. Coordinator reconciles conflicts, does not assume writer authority. All automation must apply identical rules; notifications only on meaningful deltas or blockers. Reuse verified outputs; do not re-render to transfer. Verify artifact bytes and provenance before reuse, reserve retention/backup and test independent restore. No public private evidence.

## Readiness and closure
For each affected capability and module maintain explicit POLICY_ONLY / IMPLEMENTED / ISOLATED_PASS / PRODUCTION_VERIFIED / BLOCKED (or NOT_RUN) with exact tested revision, evidence, owner, dependency, next executable action and unblock condition. Do not equate policy, PR, CI, adapter mock, or same-run reopen with production readiness. Before precision work require relevant measured executable blueprint, source SHA, target IDs, tolerance, qualified operation, matched residual and G1; before using new infrastructure require actual environment/version/license/billing qualification, atomic ownership, exact-byte preflight and native checkpoint recovery. Existing qualified independent production may continue; do not interrupt a current owner or retroactively impose a blanket stop. Unqualified dependencies block only affected work; use existing qualified route if available, never silently bypass gate. No automatic adoption or main merge.

Long-session engine acceptance: actual multi-stage native edit with measured change, in-session correction and recovery, durable checkpoint/hash and independent cross-run restore, real outputs/QA, deadline reserve and fencing, deduplication across all event types, dependency invalidation, actual dispatch verification. Test failure, stale lease, missing/expired artifact, conflicting writer, changed input and interrupted session. 60–120 minutes planning only; up to verified free runner limit, no artificial waits. Do not claim six-hour readiness from short isolated test. Complete production-bearing vertical slice before broad rollout. Track remaining work to closure, not merely document or open PR; after blocker resolution resume next uncompleted stage, not entire workflow.

# Continuous 3D authoring, recovery and world expansion
Director approved 2026-11-21. Mandatory for ChatGPT, Codex, Claude, Gemini and automations. Extends hybrid world v2, native authoring and causal retry v3; no canon or asset adoption change.

## Continuous production
Work like an experienced human operator: inspect actual UI/state, batch related edits, check meaningful visual milestones, correct and continue without routine approval pauses. Use Blender GUI/Python, native authoring tools, CLI and CI according to demonstrated capability. Use ordinary undo/redo, cancel active tools, restore mode/selection/context, copy/paste known safe values or compatible objects, reopen saved checkpoints, recover missing dependencies and resume from last verified operation. Verify actual result; never assume a click or paste worked. Never paste credentials or private lore into public destinations. Preserve original files; use versioned editable checkpoints and safe copies, not destructive overwrites.
 
## Recovery and execution
Before each batch check authority, current HEAD, file owner, inputs and actual execution environment. Save meaningful checkpoints before risky operations; inspect screenshot/log/state on errors. Recover locally first; retry bounded operations only under causal retry v3 (two same-cause failures trigger reassessment). On crash reopen last verified native checkpoint, validate dependencies, compare restored state and resume remaining steps rather than start over. Reuse successful setup, caches and artifacts by verified hashes. If a GUI is unavailable, use a qualified equivalent or hand off exact remaining operations; never claim simulated clicks or unexecuted work. Do not repeatedly restart CI for individual controls. Avoid concurrent writers and duplicate runs. Set timeout, resource budget, expected output and stop conditions; preserve failed evidence.

## Quality loop
Actual authoring → checkpoint → actual multi-view render/screenshot → independent art and structural QA → diagnose → correct → rerender → reusable artifact → next independent stage. Reports are not routine approval gates. Save native source, previews, hashes, provenance/license, run and artifact IDs, G1–G4 verdicts and next executable task. Distinguish screenshots from geometry/export/runtime verification. Separate author from independent reviewer where feasible. Stop affected work only for real capability, access, canon, safety, cost or exhausted justified recovery; continue independent safe work. No unattended execution claim unless actually scheduled or running.

## World expansion
Under Art-Directed Hybrid World Production v2, expand Windwaiting Cliff, Rilde village, meadows, forest, roads, bridges and coastline in parallel using existing owners and approved CG/canon. Increase explorable area, density, variation, life and scene quality iteratively, not endless isolated mesh refinements. Reuse verified modular buildings, rock, foliage, PBR and LOD assets; avoid repetitive placement. Validate exclusion masks, grounding, route connectivity, collision, camera, visibility and performance. Use documented provisional local coordinates; official placement and new lore remain gated. Measure target-device performance; no invented budget or density quota.

## Character expansion
After Morwen production method is validated and Morwen succeeds through applicable quality gates, reuse validated workflows to build diverse existing canonical characters and NPC candidates. Compare licensed suitable bases including native sculpt, VRoid and CC0 where appropriate; vary physique, face, hair, clothing and occupation without mere recolors. Shared rigs/materials/modules must preserve each character's individuality and provenance. New named/lore-bearing NPCs and formal adoption require approval. Prepare independent reusable modules without disrupting Morwen. Verify deformation, animation, silhouette, LOD and runtime per asset.

## Authority
Existing owning branches/PRs, one writer per file. No unauthorized main merge of asset work, canon change, public release, destructive deletion, paid service or formal adoption. G1–G4 and adaptive retry v3 remain binding. This policy authorizes routine non-destructive recovery and production, not unlimited retries or capabilities unavailable to an agent.

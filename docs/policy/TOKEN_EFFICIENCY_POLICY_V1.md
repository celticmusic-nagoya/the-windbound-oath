# Token efficiency and deliverable-first execution v1
Director-approved 2026-11-21. Applies to all TWO agents and automations. Supplements Production OS v1; no change to canon, retry v3, G1–G4 or approval boundaries.

1. Read mandatory current-main entrypoints and relevant scoped policy at task start. Within a session reuse verified content by ref/blob SHA; refresh changed pointers, canon, ownership and live job status before acting. Fetch targeted ranges, filenames and diffs instead of massive PR patches, repository sweeps or repeated full logs. Expand when needed for correctness; no skipping required checks.
2. Allocate reasoning by task complexity. Use deterministic scripts for measurements, geometry metrics, hash checks, tests and summaries; reserve intensive reasoning and independent visual review for decisions that need them. Do not duplicate analysis across agents except independent QA. No unapproved API or cost.
3. Reuse outputs only when inputs, scripts, runtime, settings, QA contract and output hashes/availability match. Preserve native checkpoints; batch actual authoring and recovery in one session; avoid per-control CI, redundant environment installs, renders and planning-only loops. Preview first with matched views; use crops/thumbnails for triage and full-resolution actual pixels for precision/final art QA. Do not mistake image counts, mesh counts or green CI for quality.
4. Use existing PR/owner, one writer and independent QA; follow Production OS locks/queue when verified. Handoff only changed task/owner, HEAD/base, source/output hashes, candidate status, method/attempts, QA, artifact IDs/paths/retention, blockers, dependencies, next executable action and stop condition. Link existing evidence rather than copying it. Keep authenticated artifact transport; no rerender just to transfer.
5. Retry v3: two same-cause failures trigger reassessment, not a hard cap. Continue bounded evidence-supported fixes, switch wasteful methods; retain cumulative ledger. Do not reduce necessary QA to save tokens.
6. Report actual changed deliverables, QA/blockers, and next action/executed automation. Routine reports target 600 Japanese characters or equivalent concise length, not a hard limit; include necessary evidence and actual visual milestones. No repeated boilerplate or unchanged reports. c/ok continue safe approved work without restating instructions.
7. Preserve full canon/source/license verification, art and technical QA, collision/traversal and actual target-device testing, security and explicit approval gates. Optimize total cost/time to accepted deliverables rather than token counts alone. Track actual usage only if available; no invented savings. Policy adoption does not verify implementation or authorize asset merges.

## Operational execution supplement — director approved 2026-11-23

Applies to ChatGPT, Codex, Claude, other agents and automations. The seven rules above remain mandatory; this supplement operationalizes them without changing ownership, canon, quality gates or approval boundaries.

- Context: use rg/grep, git diff/show, file/function inventories and JSON filters to retrieve relevant ranges. Cache verified content by blob SHA within a session; refresh live ownership, HEAD, policy, dependencies and job state before mutation. Expand context whenever correctness requires it. Store bulk geometry metrics and logs as artifacts; pass summaries and anomalies to reasoning.
- Reasoning: use low effort for deterministic checks and routine changes, moderate effort for normal integrations, high effort for architecture, root-cause analysis, complex geometry, safety, fencing and recovery where the available interface supports selection. Delegate hash checks, mesh/UV/normal metrics, projected landmarks, residual calculations, log classification and test aggregation to deterministic scripts. AI selects corrective methods and interprets results; independent visual QA remains mandatory.
- Execution: reuse existing qualified code, environments, caches and outputs only after checking input/code/runtime/settings/QA/output hashes and availability. Batch preflight, actual edits, targeted tests, correction and QA in one session; avoid planning-only stops, per-control CI and redundant installs or renders. Preview with matched views, then full-resolution precision/final QA.
- Blueprint and Session Controller: use executable target/measurement/operation IDs, coordinates, units, tolerances and dependency fingerprints. Do not edit on ambiguous observations or redesign completed specifications without evidence. Execute qualified edit, measure, residual assessment, justified correction, remeasure, materials/preview, QA and durable save. Reuse compatible checkpoints; invalidate affected stages only; isolate failures, reserve save time, resume incomplete work after verified restore and reject conflicting writers. No artificial waits. Use these engines only within their verified readiness scope; existing qualified routes may continue independently.
- Allocation: select the qualified agent from live ownership, actual availability and demonstrated capability for code, authoring, adapters, runtime integration, coordination and QA. No fixed AI roles or mandatory dependency. No duplicate owner edits, investigations or implementations except independent QA. Existing PRs and authenticated evidence references are the shared state.
- Retry: record cause hypothesis, changed method, evidence, expected outcome, budget and stop condition; follow Causal Retry v3. Do not replay unchanged failures or reset history by renaming.
- Handoff: persist milestone state (owner, PR, HEAD/base, input/output hashes, methods, artifacts/expiry, QA, dependencies, next executable operation and stop condition). Resume from verified current state rather than replaying long chat histories. Report only changed deliverables, QA/blockers and next operation/executed automation; target 600 Japanese characters, with necessary evidence exempt. c/ok prioritize execution of approved reversible scope.
- Metrics: when available record actual token usage, CI count/time, duplicate executions, checkpoint reuse, unsupported retries and time to accepted deliverable. Never invent usage or savings. Preserve source/licensing, precision blueprint and tolerance checks, G1–G4, independent art review, native reopen, security/fencing, save compatibility, WebGL and actual Android tests wherever applicable. No new expense or irreversible action without explicit approval.

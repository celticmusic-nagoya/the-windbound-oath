# 気絶（stun）専用モーション 制作仕様書（Aidan / Fiona / Lou）

作成: 2026-10-19 / 状態: **SPEC（素材は未制作・未納品・未採用）**。画像生成・正式採用・ゲームへの実装は、この仕様の確認後に別途進める。
関連: `docs/battle/faint-state-design.md`（ロジックの詳細設計）。気絶は **KO とは独立した状態**で、KO 素材（`*_ko`）は流用しない（B案）。

## 1. 目的と見た目の役割
- 「HPは残っているが、数ターン動けない」を一目で伝える。**倒れ切らない**（KO は地面に伏せて終わる／消える。気絶は膝をつく・ふらつく・浮力を失う程度で、回復すれば立て直せる）。
- 気絶中は同じポーズを保持するため、**入り（遷移）→保持（ゆるいループ）**の構成にする。
- 3人とも同じ演出文法（ふらつき→崩れかけ→ぐったり保持）で、キャラごとの特徴を出す。

## 3. 絵の共通ルール
- **正式採用済みのデザイン（衣装・配色・武器・杖・羽）を変更しない。** 既存の `damage` / `ko` / `idle` 素材と同じ線・塗り・光の向きに揃える。
- 向き・スケール: 同じアクターの `damage` / `ko` の1コマ目と同じ向き（右向き＝戦闘配置）、**身体の大きさを揃える**（頭の大きさが `damage` と同程度）。
- **足元アンカー固定**（Lou は胴体中心）。6コマ通してキャンバスサイズ同一、足元（接地点）の位置は±数pxに収める。最終コマと保持ループはキャンバス外にはみ出さない。
- 文字・エフェクト文字・集中線・星マークなどの**記号的演出は入れない**（ステータス表示は UI 側で「気絶 N」を出す）。弱いオーラや光の粒は可だが、身体のシルエットより目立たせない。
- 血・流血・過度な苦痛表現は入れない（気絶＝意識を失うだけ）。

## 4. コマ構成（全員共通・6コマ）
| コマ | 役割 | 内容 |
|---|---|---|
| 1 | 衝撃 | 待機の姿勢から、気を失う瞬間（目を見開く／よろめき始め）。`damage` の1コマ目と矛盾しない |
| 2 | 崩れ始め | 体重が抜けて傾く、膝が折れる |
| 3 | 崩れ切る手前 | 完全に倒れる直前で止める（KO との区別） |
| 4 | 保持A | ぐったりした保持ポーズ（頭が下がる・目を閉じる） |
| 5 | 保持B | 保持Aから**わずかに**呼吸でゆれる（肩・髪・羽・服が1〜3%動く） |
| 6 | 保持C | 保持Aと同じに近い。**6→4 へ繋いでループしても跳ばない**こと |
- 再生方針: 1→2→3→4 を一度だけ再生し、4→5→6→4… をループ（`hold` は「4コマ目からループ」。現行の `hold:'loop'` は先頭に戻るため、実装時に `loopFrom` を manifest に追加する想定。素材側は上の構成を守ればよい）。
- 表示時間の目安: 1〜3 は 110/130/160ms、4〜6 は 260ms 前後（ゆっくり）。最終値は実装時に調整。
- 解除時は idle へ戻る（逆再生はしない。実装側で idle へ切替）。

## 5. キャラクター別の指示（デザインは既存を厳守）
- **Aidan**: 剣を握ったまま膝をつく／切っ先が地面に付く程度まで。倒れ込まない。保持は片膝立ちでうなだれる（KO は仰向け／伏せ）。
- **Fiona**: 杖（または弓）を支えにして崩れる。保持は杖にもたれて座り込む／ひざをつく。髪と服がゆっくり揺れる。
- **Lou**: 浮遊する妖精。羽ばたきが乱れ、高度が下がる。保持は低い位置でふわりと浮いたまま目を閉じ、羽をゆっくり開閉（地面に落ちない。KO の落下とは別）。足元アンカーではなく**胴体中心**を揃える。

## 6. キャンバスと切り出し（実装側の都合・参考）
- 切り出し後の1コマの参考サイズ（同じアクターの既存モーションに合わせる）: Aidan ≈ 794×529 / 750×500、Fiona ≈ 782×521 / 856×571、Lou ≈ 790×527 / 786×524（3:2 キャンバス、`tools/battle/cut_party_sheets.py` で切り出す）。

## 7. 検収チェックリスト（採用判断の前に）
1. 6コマが同一キャンバスで、コマ間のはみ出し・切れがない。
2. 足元（Lou は胴体中心）が全コマで揃っている。
3. 衣装・配色・武器が採用済みデザインと一致（差異なし）。
4. KO と見分けがつく（倒れ切っていない・消えない）。
5. 6→4 のループで跳びがない。
6. 背景が完全透過（アルファ1〜8のもやなし）。
7. 原本の SHA-256 を記録し、`assets-originals/` に原本を保存。
- **納品されても、正式採用の指示があるまで台帳は `PENDING`（候補）のまま。実装しない。**

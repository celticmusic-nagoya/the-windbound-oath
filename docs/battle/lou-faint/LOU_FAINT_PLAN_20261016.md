## 2. 最大の論点：「ルーのHPが0になる」手段が現状ない
指示書の「HP0で気絶」を成立させるには、ルーが被ダメージ対象になる**新規の戦闘ルール**が必須。これは戦闘バランス変更に該当するため承認が要る。選択肢：
- **案A（推奨）**：ルー専用HP（例 最大HP固定値）を新設し、ボスの全体攻撃「破砕斬」等でのみ巻き込み／もしくは敵通常攻撃の一定確率でルー狙い。通常戦未登場のため影響はレイダー戦に限定。
- 案B：HPを持たず「特定攻撃で気絶」（フラグ制）。UI/保存が単純。「HP0」表現と食い違う。
- 案C：現状維持（気絶は演出のみ）。仕様の意図を満たさない。
→ **要決定**：どの攻撃がルーに当たるか／ルーのHP値／回避可否（evade素材あり）。

## 3. 既存仕様との衝突箇所
1. **全滅/やり直し判定**：現在は「エイダンorフィオナのHP0で時間巻き戻し」。ルーは判定に含めない（指示どおり）ため、`rbHP<=0||rbFHP<=0` は無変更で良い。ただし「ルー気絶中にエイダン/フィオナ1人がHP0」でも従来どおりやり直し＝整合。
2. **support() の前提**：`rbBoss<=0`・victory以外では必ず動く。気絶中は return false にするガードが必要。lastSupportRound の扱い（気絶中にカウントを進めるか）を決める必要あり。
3. **最終祝福（finalBlessing）**：Phase3突入で必発・blessingUsed 1回限り。気絶中にPhase3に入った場合、(a)スキップして消費しない／(b)復帰後に持ち越し／(c)消費して不発 を要決定。enrageMoment/enragePending/enrageFlow のフローと競合しやすい最重要箇所。
4. **BattleActorState**：health()=null の特例（resting→idle）を外し、ルー専用HPを返す必要。`sync()` が hp<=0 で ko に自動遷移し、`recover()` が復帰を担う（既存の通常戦復帰と同じ仕組みが使える）。ko中は他の一時ポーズ（heal/blessing）がブロックされる設計＝気絶中の演出誤再生を自然に防げる。
5. **ターゲット選択**：allies() にルーを入れない（アイテム/回復対象外）か、入れる（ポーション等で気絶回復）かの仕様判断が必要。入れる場合 BattleTargetSelector/UIState/CommandGate の再検証が必要で影響大。**初回は入れない案を推奨**。
6. **BattleStatus.render / buffParty**：対象がaidan/fiona固定。ルー自身へのバフ・気絶ターン表示（UI）を出すなら拡張が必要。buffParty は ally.hp()>0 フィルタ済みでルーは対象外のまま。
7. **UI**：HP/気絶表示の置き場所（rbLou周辺）、モバイルレイアウト（tests/battle/raider_mobile_layout.py）への影響。
8. **KO素材**：ルーKO素材（新6コマ・渦巻き目と星）は採用確定。ただし現行 lou_ko.png との差し替え／MANIFESTへのmotion登録は別承認（素材統合）。復帰時の演出（起き上がり）素材は未制作。
9. **セーブ形式**：戦闘中状態は非保存のため変更不要（セーブ形式維持）。
10. **ENEMY側**：通常戦のFIELD_BUFFや敵ステータスは触らない。raider専用に限定。

## 4. 詳細仕様の推奨案（提案値の取り扱い）
| 項目 | 提案値 | 推奨・論点 |
|---|---|---|
| 気絶期間 | 3ターン | 「ターン」を**ラウンド**と定義（既存ラウンド=ルー行動1回）が最も既存と整合。3Rは短い戦闘では気絶中に最終祝福を逃し得る→(3)の扱いとセット |
| カウント方法 | — | 気絶したラウンドは数えず、以降の各ラウンド終了時（BattleStatus.tick同タイミング）に−1。3回目の終了で復帰 |
| 復帰HP | 最大HPの30% | 端数切り上げ、最低1。ルーHP新設なら最大値が決まって初めて確定 |
| 復帰ラウンドの行動 | 未定 | 復帰処理を「ラウンド終了時」に行い、**次ラウンドの敵フェイズから行動可**にするのが最も衝突が少ない（復帰直後に同ラウンドで二重行動しない） |
| 再気絶 | 未定 | 制限なし・回数無制限、毎回3R。復帰直後の連続気絶防止に「復帰したラウンドは被弾対象外(1R無敵)」案も（バランス変更になるので要承認） |

| やり直し時 | — | 時間巻き戻しでルーも全回復・気絶解除 |

# 追補（21:25指示反映）：ランダム復帰方式
## 確定方針 / 仮案
- 確定方針：KO演出（渦巻き目・星）採用／気絶中は支援不可／ルー気絶だけでは敗北しない／残りターン非表示／復帰ログ「ルーが目を覚ました！」／UIは「ルーは気絶中…💫」のみ
- 仮案（未確定）：気絶後2ターン目に50%で復帰、起きなければ3ターン目に必ず復帰／復帰HP最大の30%
- 復帰は「気絶したラウンドを0とし、以降のラウンド終了処理で1→2→3と数える」定義を推奨（現行のtickと同位置）。期待気絶は平均2.5ラウンド（2R復帰50%、3R復帰50%）。

## ランダム化で増える論点
1. **乱数源**：既存は BattleStatus.dodges(…, rand=Math.random) の引数注入方式。復帰判定も同様に `rand` 注入可能な関数で実装し、テストは固定値で決定的に検証（実Math.random依存のテストは作らない）。
2. **非表示の徹底**：残りターンをDOM・title・aria-label・ログ・コンソールに出さない（BattleStatusは残りターンをtitle/aria-labelに出す設計のため、ルー気絶を同じrenderに流用しない）。内部カウンタはdev限定表示も不要。
3. **最終祝福との競合が悪化**：復帰が確率のため、Phase3突入時に気絶している確率が上がる。推奨：気絶中は最終祝福を消費せず(blessingUsed=false維持)、復帰した次の支援機会で実行する“持ち越し”方式（enragePending が気絶中に残留しないよう整理が必要）。要承認。
4. **支援スケジュール**：lastSupportRound 判定が復帰時期に依存。復帰直後の支援を即行うか、通常間隔に従うかを決める（推奨：通常間隔に従う＝バランス変更を最小化）。
5. **危機時の癒し**：ルーが気絶している間は癒しが来ないため、レイダー戦の実質難度が上がる。「気絶期間の平均2.5R」×被弾頻度で戦闘バランス影響が出る → 実装前にシミュレーション（ルー被弾率×気絶期間）で難度への影響を確認すべき（敵ダメージ・HP数値は変更しない前提）。
6. **やり直し（時間巻き戻し）**：ルー気絶・カウンタも初期化。乱数の再現性は不要。
7. **復帰HP**：ルーHP最大値が未定のため30%は未確定。丸めは切り上げ・最低1を推奨。

## 追加テスト項目
- 乱数固定：2R目 rand<0.5→復帰／rand>=0.5→継続、3R目は乱数に関係なく必ず復帰（rand=0.999でも）
- 境界値 rand=0.5ちょうどの扱い（<0.5で復帰に固定し仕様化）
- 気絶前後で乱数消費回数が不変（無関係な乱数列をずらさない）
- 残りターンがDOM/title/aria/ログに一切出ない（文字列走査テスト）
- 「気絶中…💫」表示・「目を覚ました！」ログが1回だけ出る
- 連続気絶時に毎回カウンタが初期化される
- 統計テスト（固定seed外れ値回避のため回数大で2R復帰≈50%の範囲確認）は補助とし、合否は決定的テストで判定

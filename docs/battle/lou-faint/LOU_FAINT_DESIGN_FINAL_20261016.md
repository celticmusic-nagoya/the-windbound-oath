# ルー気絶・ランダム復帰 最終実装設計とテスト手順（コード変更なし）
承認済み仕様: HP新設なし／破砕斬実行時のみ33%で気絶／気絶中の再被弾は無効（カウント不変）／気絶R=0、以降ラウンド終了時に1,2,3／2で50%復帰・3で必ず復帰／復帰ラウンドは通常支援なし／気絶中Phase3は最終祝福を保留→復帰時に一度だけ／気絶中の勝利は勝利ポーズ優先／30%案破棄／KO演出採用／新KO素材接続は別工程。作業ブランチ案 `feature/lou-faint-recovery`（未作成）。

## 1. 確認①：シミュレーションの復帰カウンタのずれ → **ずれあり、修正済み**
- 旧シミュレーション(sim2)は、気絶したラウンド自身の終了時にもカウンタを+1していたため、**仕様より1ラウンド早く**復帰判定していた（気絶継続の平均 2.47R）。
- 修正(sim3)：気絶ラウンドの終了処理では加算しない（`justFainted`フラグ）。R+1終了=1、R+2終了=2（50%判定）、R+3終了=3（必ず復帰）。気絶継続は 3R か 4R（R自身を含む）。
- 実装設計への反映：破砕斬(敵フェイズ)での気絶と、同ラウンド末のtick処理は同一関数内で連続するため、**「このラウンドで気絶した」フラグで同ラウンド末の加算をスキップ**する。これを忘れると旧シミュレーションと同じ1ラウンド早い復帰になる。テストで固定（下記T2-T4）。
- 再評価結果（33%、5000戦、乱数固定seed）:

| 条件 | 気絶回数/戦 | ルー不在率 | 支援回数/戦 | DEF付与率 | Phase3突入時に気絶 | 最終祝福の発動 | 保留の遅れ |
|---|---|---|---|---|---|---|---|
| 現行（気絶なし） | 0 | 0% | 5.5 | 61% | 0% | 100% | – |
| 旧カウント(ずれ)33% | 1.67 | 24% | 4.7 | 56% | 18% | 100% | 0.26R |
| **修正カウント33%** | 1.49 | **29%** | **4.3（約22%減）** | **52%** | **25%** | 100% | 0.74R（0/1/2Rが約 4:4:2） |
| 修正カウント50%(参考) | 2.10 | 41% | 3.7 | 48% | 36% | 100% | 0.75R |
気絶継続は 3R:4R≒54:46。破砕斬は戦闘あたり約5.3回。※増援・穢れ供給・実操作は未反映の概算。

## 2. 確認②：乱数追加が既存の回避・会心判定を変えない設計
現状の乱数利用: 回避 `BattleStatus.dodges`(`p>0&&rand()<p`、eva_up無しなら乱数を引かない)、会心 `BattleCritical.calculate`(`random=Math.random`、canCrit時のみ)、ルー飛行(`battle-lou-flight.js` の見た目用Math.random)。いずれも未シード。
設計:
1. **専用の乱数源**：新モジュール `js/battle-lou-faint.js`(frozen API)が自前の `rand`（既定 `Math.random`）を保持。回避・会心の関数とそのシグネチャ、呼び出し順は一切変更しない。
2. **乱数を引く条件を最小化**：(a)破砕斬実行時、**ルーが気絶中でない場合のみ** 1回（33%判定）、(b)カウント2到達時のみ 1回（50%判定）。気絶中の再被弾・カウント1・カウント3では引かない（3は必ず復帰）。
3. **引く位置**：破砕斬ブロック内の dodge 判定(dodgeA/dodgeF)とダメージ適用・ログの**後**に配置。既存の引く順序を前後させない。
4. **テスト用注入**：`WINDBOUND_DEV`時のみ `BattleLouFaint.setRandom(fn)` を許可（既存 instantKill と同じ dev ガード）。製品では差し替え不可、公開APIは frozen。ルー用乱数を固定しても回避・会心が影響を受けないことをテストで担保。
5. 判定式は `rand() < 0.33`、`rand() < 0.5`（境界値は未満で気絶/復帰）。定数は1箇所に集約し、数値は承認値のみ（0.33 / 0.5 / 3）。
6. シミュレーションでも乱数ストリームを分離し、気絶有無で他ストリーム（戦闘ラウンド列）が一致することを確認済み（200戦一致）。

## 3. 最終実装設計
状態（raider戦ごとに初期化、非保存）: `faint: null | {count, justFainted}`、`finalBlessingPending: bool`。
- **気絶**: 破砕斬実行ブロックで、ダメージ適用後に `LouFaint.onSmash()`。`faint!==null`なら何もしない（乱数も引かない）。そうでなければ `rand()<0.33` で気絶：`faint={count:0,justFainted:true}`、ko表示（BattleActorStateの専用経路）、ログ「ルーは破砕斬の風圧で気絶した！」。
- **支援停止**: `support()` 冒頭に `if(LouFaint.active) return false`。lastSupportRound は更新しない。`finalBlessing`/`enrageMoment` は後述。
- **ラウンド終了**: 既存の `BattleStatus.tick` 直後、敗北判定の前に `LouFaint.endOfRound()`：justFainted なら解除のみ(加算しない)、そうでなければ count+1。count==2 なら `rand()<0.5` で復帰、count>=3 は必ず復帰。復帰時：状態クリア→ko解除(`recover`相当)→ログ「ルーが目を覚ました！」→pendingがあれば一度だけ最終祝福。
- **復帰ラウンドの支援**: 復帰はラウンド末(支援枠通過後)なので当該ラウンドの通常支援は自然に無し。次ラウンドから既存の `rbRound-lastSupportRound` 条件で再開。
- **最終祝福**: `enrageMoment()` 冒頭で気絶中なら `finalBlessingPending=true` のみ立てて return（blessingUsed / enragePending / enrageFlow は触らない）。復帰時 `if(pending&&!blessingUsed) { pending=false; finalBlessing() }`。`blessingUsed` ガードで二重発動防止。発動順は「目を覚ました！」→祝福台詞。
- **勝利**: finishRaider の victory 設定が気絶koに勝つよう、気絶専用経路を `BattleActorState.set('lou','victory')` で上書き可能にする（現行 resting()/ko優先規則は HP非保有のため気絶専用フラグで分離）。
- **リセット**: startRaiderBattle/beginRaider/やり直し/generation変更で faint・pending・タイマーを全クリア。
- **UI**: ルー付近に「気絶」バッジ（絵文字💫可）。残りターン・カウンタ・確率はDOM/title/aria-label/ログ/コンソールに出さない（BattleStatus.render は使わない）。
- 変更しない: 敗北判定、エイダン/フィオナ/敵の数値・ダメージ式、通常戦、セーブ形式、バトルUI構成、新KO素材（現行lou_ko.pngで暫定表示、差替えは別工程）。

## 4. テスト手順（実装承認後）
全て乱数を固定して決定的に。実機フローは tests/run_python.py + Playwright(PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium)、実際の開始関数(startRaiderBattle)経由・生成世代バイパス不使用。
**A 気絶トリガー**
- T1 破砕斬のみで判定、単体攻撃/狂爪連撃/腐蝕/供給/角笛では乱数を引かない・気絶しない
- T1b 33%境界: rand=0.329→気絶、0.33→気絶しない
- T1c 気絶中の再被弾で乱数を引かず、カウント不変
**B カウンタ（確認①の固定）**
- T2 気絶ラウンドR末はカウント0のまま（加算なし）
- T3 R+2末: rand=0.49→復帰、0.5→継続。R+1末では復帰しない（ずれ検知）
- T4 R+3末は rand=0.999 でも必ず復帰。復帰後最初の通常支援はR+3(早期復帰時)/R+4から
- T5 復帰ラウンドに癒し/加護が出ない・次ラウンドは通常条件で再開
**C 最終祝福（確認④）**
- T6 気絶中Phase3突入：祝福未発動、blessingUsed=false、enragePending=false、enrageFlow=null
- T7 復帰時に一度だけ発動、ログ順「目を覚ました！」→祝福、二重発動しない（復帰直後に再度Phase3 tick/enrageMoment再呼出しでも1回）
- T8 気絶中に勝利/やり直し/中断→pending持越しなし
- T8b 気絶していない状態でPhase3：従来どおり即発動（回帰）
**D 敗北・進行**
- T9 ルー気絶のみで巻き戻しにならない／エイダンorフィオナHP0は従来どおり
- T10 気絶中の勝利は勝利ポーズ、タイマー・バナー残留なし
**E 乱数独立（確認②）**
- T11 ルー乱数を変えても回避(eva_up)・会心の結果が不変／気絶機能無効時と有効時で回避・会心の乱数引き順が同一
- T12 気絶していない経路では専用乱数を引かない(呼び出し回数カウント)
- T13 setRandom は WINDBOUND_DEV でのみ有効
**F UI・非表示**
- T14 「気絶」バッジ表示、復帰ログ各1回
- T15 DOM/title/aria/ログに残りターン・確率・カウント数字が出ない(文字列走査)
- T16 モバイル幅(raider_mobile_layout拡張)で重なりなし
**G 回帰**
- T17 raider_mobile_layout, lou_idle_real_flow, ui_command_safety, int02_routes_real_adapter, int02_p0_start_failure, battle_admission_adapter, 通常戦テスト、Full100既存PASS群が不変
**H 難易度再検証（確認③）**
- T18 実機フロー(実際のstartRaiderBattle/敵フェイズ)で固定seed 50〜100戦を自動操作し、33%案の ルー不在率・支援回数・DEF付与・戦闘ラウンド・やり直し率 を「現行実装」と比較。シミュレーション(不在率29%/支援4.3回)との乖離が大きい場合は報告して承認を仰ぐ。数値は変更しない。
- 事前に「現行(変更前)」の実機ベースラインを取る（読み取り実行のみ）。
**独立レビュー**: 戦闘ロジック変更のため Codex 独立レビュー必須。Claudeは完了/VERIFIEDを自己判定しない。

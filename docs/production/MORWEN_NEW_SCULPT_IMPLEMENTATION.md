## Blenderでの制作手順

着手解除後に実行する手順。既存候補のコピーを出発点にする場合でも、失敗済みcage・局所fairing・quad patchのコードや変形済み形状は使用しない。

1. **準備。** Blender 4.3.2で既存参照シーンを複製し、原本の参照写真はロック、レンダー非表示。候補フォルダを既存の `assets/candidates/morwen-rebuild-01/` 配下に分ける。固定カメラの位置・等方スケール・接地ガイドを `review-settings.json` に保存。全身高を比較用に正規化する。画像を人体向けに伸縮しない。取得済み69件から可視輪郭と仮骨格を別コレクションに置き、点の採否と不確実性を保存する。
2. **正面と側面を交互に量塊化。** 複製した参照シーン内の空の造形コレクションで、頭蓋〜顎、胸郭、骨盤、四肢の粗い体積を追加。胸郭と骨盤を別量塊にして重心と骨盤の傾きを決める。肘・膝の向き、踵と前足部、支持の見え方を固定四方向と斜めを切り替えて確認する。7.5〜8頭身は候補の頭蓋頂／顎／足底で検証。粗い量塊は保存し、最終形状には面遷移を彫り直す。既存参照は観測可能な領域だけを登録比較する。
3. **体型と関節を彫る。** 粗量塊を連続面にする必要がある箇所だけ、作業コピー上でVoxel Remeshを使い、指など細い部位は別に保持する。Grabで全身から中程度の量塊に移り、Clay StripsとSmoothで面を繋ぎ、必要な稜線はCrease/Scrapeで面を作る。肩は鎖骨の傾斜、三角筋の付着、前後の腋折れ、上腕の正面と側面を一緒に確認。胸郭・骨盤は輪郭幅、前後の厚み、臀部と大腿の遷移を斜めで点検。膝は前面の膝蓋部から腱・脛への移行と後面の曲げ側を作り、下腿の最大部の高さと足首・踵への流れを整える。初期の左右対称は補助手段。全身で見える非対称を別パスで付け、想像した関節左右差は台帳に仮説と記す。
4. **最初の実成果物。** 編集可能な体型スカルプト1点、原寸注釈との固定四方向比較、左右斜め、肩腋・膝のクローズアップ、想定ゲーム表示サイズ、部位別の判定表を提出。既存候補と並べる時はカメラと照明を固定。肩30°/60°、膝45°/90°の可動意図を可視化する簡易ポーズは、本番ウェイトとは別系統で保存。G2前の修正は身体の量塊と姿勢に集中する。
5. **G2身体承認後にリトポ。** 保存スカルプトを別コレクションに固定し、手設計の頂点スナップ／Shrinkwrapで適合させる。肩腋・肘・股・膝は主要折れと伸縮側を流れるループを先に置き、可動部の集中点を避ける。投影ずれと貫通を仮屈曲で確認し、粗い候補段階でポール位置や密度を固定しない。顔・髪・服・装備は確認済みv5.61の見え方を設計し、部位ごとの形状承認後に目口の開閉ループ、頭皮に根を持つ非対称ボブ、帽子・衣装・装備の干渉を仕上げる。
6. **材質・リグ・ゲーム出力。** 承認済み形状をGame meshにベイク。色はsRGB、法線とroughness/metallic/AOは非カラー。意図した接触を記録し、つぶれ・滑り・突き抜けは本番骨とウェイトで修正する。idle、歩行、走行、詠唱、瞬き・口形状を確認し、masterを残した状態でGLBとLODを別成果物として保存する。

## 自動化と手作業

- **Python／Actionsで自動化可能。** 既存の固定版と入出力manifestを再利用。原画sha・寸法・座標範囲、参照の投影と方向、シーン再オープン、有限座標・面数・意図しない開境界・縮退・固定三角化での交差、UV、ウェイト正規化・ボーン、GLB構文・拡張・テクスチャ・予算を検査。保存済み原本を自動スクリプト無効で開き、変更のあった候補だけ固定ビューを出力する。入力commit、BlenderとPython、書出し設定、比較カメラ、ソース署名を残し、失敗ログもArtifactへ保存。headless担当は同じ保存入力の検査再現まで。
- **手作業。** 立体の量塊、肩腋と下肢の曲面、見えない構造の解釈、頭部の個性、髪の束と衣装の動き、最終エッジフロー、補正ウェイト、アニメーションの演技、照明と実機の見え方は担当者が判断する。自動数値は承認票と分ける。
- **AI 3D補助。** 既存資料で確認したTripoSRは、使用可能なローカル環境と権利確認済み入力が揃えば、原本を送信せず量塊の検討資料を作る用途に限り検討できる。単眼の隠面を補う性質があり、四方向と一致する人体・変形・顔・髪の保証はない。SF3Dの商用条件、Hunyuan3D-2mvの地域制約は既存監査の判断を継承。今回の標準工程はAI生成、追加課金、GPU runnerを前提にしない。[既存技術・ライセンス調査](MORWEN_PRODUCTION_METHOD_REVIEW_01.md)
- **造形担当が未確保の場合。** Codexは原寸注釈の機械検証、参照sceneとカメラの配置仕様、空テンプレートの設計、検査コードの設計、工数表の準備まで進められる。別担当が独立レビューを引き受けられる場合は第二注釈を先行できる。既存CC0・AI出力・Python生成を完成品質の代替にせず、担当を確保するまで量塊以降はBLOCKEDとする。

## G1〜G4、停止条件、後工程の予算

| ゲート | 証拠・判定担当 | 停止条件 |
|---|---|---|
| G1 来歴・登録 | Codexが固定SHAと画像の役割を検証。別担当の第2注釈についてIDごとにdu/dv、ユークリッド距離、区間を比較。美術担当が非重複区間を判定 | Layer 0の身体参照来歴は既存PASS。登録は第2注釈と判断が必要。未校正は見かけ寸法のみとし、物理寸法は保留。v5.61不足時は正式外観BLOCKED |
| G2 独立美術 | 固定4＋斜め2、局所clay、ゲーム表示、外観工程では材質・色・装備対応も確認。肩の急変、腋の彫り込み、膝の折れ、量塊・接地破綻を部位別に判定 | 一つでも重大欠陥、観測区間から外れる理由が未合議、または独立レビュアー不在なら停止。身体承認前に最終リトポへ進まない |
| G3 技術と変形 | リガーとCodexがmesh・UV・PBR・出力を検査。本番ポーズで意図しない自己交差、反転、縮退、関節潰れがないこと、足接地・瞬き・衣装干渉を確認 | 意図しない貫通／反転／縮退、書出しによる破綻、承認済み描画予算超過で停止 |
| G4 WebGL・Android | 基準版と候補版を同一ビルド経路・カメラ・アクション・キャラ数で比較し、最低対象端末とブラウザで実機計測。ランタイム担当が判定 | 対象機器、同時表示数、動作シーン、予算の未承認、実機未測定、重大回帰で停止 |

最適化はポーズと外観の承認後に行う。先に対象機器と現行ベースラインを取得し、解像度、最大同時表示数、暖機／計測時間、許容フレーム時間、ロード容量とGPUメモリ相当の枠を固定する。企画用の仮上限はLOD0 35k三角形、LOD1 18k、LOD2 8k、最大4ウェイト／頂点、LOD0で材質ドロー目安6以下。髪・マントなど透過部分は過描画も測る。仮値は実ゲームの採否基準として承認されておらず、形が崩れる場合は負荷の原因を測った上で配分を変える。LOD0で顔と眼鏡・肩・帽子・裾の輪郭を守り、遠距離では細部から減らす。テクスチャは圧縮前後の見え方を確認し、KTX2やメッシュ圧縮はローダー対応と実測メリットが確認された場合に使用。実機ではp95フレーム時間、draw calls、テクスチャ／GPUメモリ相当、転送量と初回表示時間、LOD切替とタッチ、描画回帰を記録する。

同一原因・方式での失敗は既存台帳に記録し、同じ形状操作を設定だけ変えて反復しない。造形開始時に担当、工数、承認済み登録、出力先を再確認する。今回の成果物は設計書。造形、改変、再レンダリング、Actions起動、公開、mainマージは行っていない。

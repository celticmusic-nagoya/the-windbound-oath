## 制作方式の選定

**第一候補は方式C。取得済みの未変形CC0 stylized femaleを造形の出発点にして、作者が全身をデザインスカルプトし、独立美術QAで形状を承認してから変形用トポロジーを設計する。** 肩・腋・膝の旧形状や境界、頂点番号、UV、面接続を維持することを採否の制約にしない。健全な部位の接続を転用する場合は承認済みスカルプトとの一致と屈曲で判断する。方式Aの継続と区別する構造的な変更は、目標面を先に作者が作り、接続をその面と変形要件に従わせる点にある。

**代替候補は方式D。** CC0素体から胸郭・骨盤・四肢の主要量塊、肩と膝の移行部、姿勢を連続面として作り直す費用が、粗い自作量塊から始める費用と同等以上と見積もられたら切り替える。方式Bは比率とリグ試作の比較用に限る。既存資料からMPFBの方がモルウェンに近いという証拠は得られていない。

**採用状態は条件付き。** 計測注釈のレビュー、未変形素体の四方向・斜め比較、美術担当による工数比較を経て素体を確定する。今回の新規造形は0件。体型スカルプトの仮説は、胸郭から上腕、骨盤から足底までの大きな面を作者が再設計すると、見かけ幅と側面・斜めの面遷移を両立できること。前回の局所欠陥を比較基準に、G2で別担当が判定する。

## Layer 0 測定仕様

1. **座標とビュー。** 原画座標は左上原点、右向きu、下向きv、整数位置を画素中心とする。原画とcrop、リサイズ画像の座標を混在させず、表示用変換と逆変換を記録。既存Blender sceneは+Z上・正面カメラ−Y・背面+Y・右−X・左+X。右画像は画面右向き、左画像は画面左向き。人物基準の左右、画面左右、カメラの位置を別フィールドに記録。正面と背面で人物左右の画面対応が反転する。膝・足・腕は各側別々に注釈し、左右反転による補完を避ける。
2. **投影の検証。** 各ビューに髪頂・顎・見える皮膚境界・袖や布の境界・同側の上下アンカーを重ね、共通アンカーで等方スケールと平行移動を当て、アンカー外の点・水平線の残差をビュー別に記録する。面の見え方、足裏の露出、重なり・姿勢差、左右での立ち姿も比較。カメラ情報や対応する3D基準がない状態では、残差を透視、姿勢、作画差に一意に帰属できない。今回の目視ではprofileで腕と胴が重なり、四方向で足底の見え方が異なる。原画は未校正、原画の正投影／透視の確定はBLOCKED。既存正投影カメラは出力側のみ。解除には原画の作成カメラまたは独立した対応点と校正根拠が必要。校正できなくても、観測区間と並列比較で身体の美術評価は可能。
3. **尺度と床。** 各ビューで支持足の接地候補を左右別の区間として取り、傾き・靴下などで曖昧な場合は根拠を注記。正背面の体幹中心線と側面の支持位置を個別に記録する。適用する場合は `u'=s(u-u0)`、`v'=s(v_ground-v)` の等方登録を使い、顔・胴・脚別の伸縮はしない。共通スケールが合わなければビュー別変換の差を公開する。2.0のscene canvasや旧946pxは物理身長の根拠にしない。alpha>0のbboxはゴミを含む。輪郭線は手動注釈で、その原画座標を保存する。

| ランドマーク | 注釈方法と区分 |
|---|---|
| 頭・帽子・顎 | 可視の髪頂、顎の外周最下点を別々に観測。頭蓋頂は遮蔽されるため仮説区間または未測定。帽子は外観用の別輪郭 |
| 肩・腋 | 左右の三角筋外周が上腕へ移る輪郭点と、見える腋折れを観測。肩峰・上腕骨頭・関節中心は推定。肩幅の高さは左右の外周点と別に定義 |
| 胸郭・腰 | 体幹側縁と可視の腰のくびれを高さ付きで記録。布・腕の外周をタグで区別し、胸郭の骨性境界は推定 |
| 骨盤・股関節 | 腰から大腿に移る側縁／衣類の境界／股の見かけ位置を観測。腸骨稜や大腿骨頭、衣類下の輪郭は推定または未測定 |
| 膝・足首・足底 | 正背面の内外縁、profileの膝前後縁、左右の踵・前足部・接地候補を観測。膝中心、衣類下の膝蓋骨、深度の違う接地点は推定 |
| 手・姿勢 | 手先、可視の手首外縁、腕の重なりを左・右別に記録。重なった側の関節を反対側から鏡写ししない |

4. **データと誤差。** 次工程のJSON/CSVは `source_ref, image_sha256, view, camera_side, subject_side, feature, surface, visibility, status, u_px, v_px, bounds_px, method, annotator, notes` を保存。statusは観測／推定／未測定。観測でも輪郭を定義する最大・最小位置を残す。二人が独立して注釈し、端点ごとに各区間を包む範囲と注釈者差を報告する。画素量子化±0.5pxを含め、トレース・登録残差・姿勢／遮蔽要因は別欄に保持。不明な系統誤差を0に置かない。幅は端点区間の差の範囲、頭身は `(v_ground-v_crown)/(v_chin-v_crown)` を共有変数のまま区間端で評価する。旧正面暫定値57±20、顎183・足底1003を仮に固定すれば約6.62〜8.74頭身となる。これは頭蓋頂仮定だけの感度で、7.5〜8頭身の設計目標を実測で証明できないことを示す。
5. **形状比較の出力。** 画像外形は注釈した輪郭・同じvでの見かけ幅。旧bandはsource頂点ID集合のbbox。3D実断面は固定した姿勢・座標・三角化の評価メッシュと平面 `Z=z` の交線で測る。連結成分を胴、左右肢に分け、幅・厚み・切断位置・変換を記録。比較可能な直接観測区間では輪郭法線方向の距離中央値／95パーセンタイルと被覆区間を報告し、根拠のある登録がないビューでは並列美術比較を主とする。許容値は測り直しとゲーム表示条件の確認後、独立レビューで候補を見る前に固定。区間の重なりのみでG2を合格にしない。

- **Hunyuan3D-2mv**（2025-03-18） 多方向Shapeモデル。公式の入出力・前処理に従う必要があり、未校正4枚から正解人体を推定できる実証はない。2.0系は形状約6GB／形状とテクスチャ約16GB VRAMの公式目安。meshをGLB/OBJで交換可能で、ローカル連携アドオンもある。Tencent Community Licenseの地域制約は出力を含むためグローバル配布を想定する本候補では見送り。[実装・公開日](https://github.com/Tencent-Hunyuan/Hunyuan3D-2) · [利用条件](https://github.com/Tencent-Hunyuan/Hunyuan3D-2/blob/main/LICENSE)

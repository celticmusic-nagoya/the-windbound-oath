## 1. 維持する Phase 1 の確定仕様（変更しない）
【事実】 `height.levelHeight=56`（実行時 world px。`world.unitScale=2.5` は再度掛けない）／`blockedAtLevel(x,y,level)` による高さ別衝突／level 0・1 の切替は connector の端点帯のみ／`lift(x,y,level)` は level 固定量（connector 内は補間）／`overpasses` 下のキャラは `deck.z-1` で描画／キャラの z は足元 y（level>0 は +1）／セーブ互換（level は加算フィールド）。画像の都合でこれらを変えない。

## 2. 既存モス素材との整合条件（実測）
【事実】`img/field/moss/art` の納品素材のうち manifest で寸法が引ける 68 点は、**すべて PNG = world 寸法のちょうど 2.0 倍（@2x）**、RGBA、足元は world 寸法の**下中央（bottom-center）**。例: `rock_moss_01` 200×205 = 100×102.5、`prop_bridge_wood_01` 440×164 = 220×82、`ruins_stone_01` 180×163 = 90×81.5。
【事実】既存素材の見た目の目安（不透明画素の統計。判定の参考値であり規格ではない）:

| 素材 | 輝度平均 | 輝度 p5 / p95 | 彩度平均 |
|---|---|---|---|
| rock_moss_01〜03 | 0.41〜0.43 | 0.06〜0.11 / 0.81〜0.83 | 0.73〜0.76 |
| ruins_stone_01/02 | 0.39〜0.40 | 0.13〜0.14 / 0.71〜0.74 | 0.65〜0.69 |
| anc_arch_broken_01 / anc_standing_L_01 | 0.38〜0.39 | 0.05〜0.08 / 0.84〜0.88 | 0.61 |
| prop_bridge_wood_01 / post_01 | 0.37〜0.39 | 0.06 / 0.81〜0.85 | 0.58〜0.67 |
| tree_ancient_sentinel / great | 0.42〜0.43 | 0.17 / 0.77〜0.80 | 0.48〜0.52 |

【提案】整合条件（検収で数値化する）:
1. PNG 寸法 = world 枠 × 2 ちょうど（@2x）。@4x を使う場合も world 枠とアンカーは同じ。
2. 画風: 既存と同じ「高精細なピクセルアート調の手描き・やや斜め俯瞰・左上光源」（`docs/art/chatgpt_moss_forest_map_brief.md` §1）。深緑・苔緑・灰・アンティークゴールドの低〜中彩度。
3. 輝度: 不透明画素の輝度平均 0.35〜0.46、p5 ≥ 0.04、p95 ≤ 0.90（黒潰れ/白飛びなし）。上表の範囲を逸脱するときは理由を記録する。昼・夕・夜の色補正（`field-timeofday.js` のグレード層）をかけても輪郭が読めること。
4. 透過: 輪郭型は実アルファ。白い縁取り（α<255 で輝度>0.9 の画素）が出ないこと。床板・連結タイルの連結辺は不透明で、端に透明余白や黒線を置かない。
5. 影: 地面影板・床・人物・光源を焼き込まない（部品ごとの禁止事項は §7）。
6. 比較の方法: DEV マップに仮置きして既存の `rock_moss`/`ruins_stone`/`prop_bridge_wood` と並べ、PC・縦・横で確認する（実機は作者）。

## 3. アンカー・足元投影・二重 lift の責任範囲
【事実】 Phase 1 の DEV 見た目（`height.visuals`）は**絶対の見た目座標**で、lift が座標に焼き込み済み（例: 橋床 visual は `y=424 = 論理 480 − 56`、高台 `plateau_top` は walk 矩形 y=120 に対し visual y=64）。スプライト（主人公・フィオナ）は `lift()` を描画側が `translateY` で一度だけ適用。静的オブジェクト（宝箱・シンボル）は論理座標＋`staticLift`。

【提案】責任の分離:

| 層 | 持つもの | 所有者 | lift |
|---|---|---|---|
| 論理層 | walk 矩形・connector・overpass・blocker（地面基準の world 座標） | map JSON / height spec | 受けない（論理は常に足元） |
| 配置層 | 素材の登録（`id`・種別・論理アンカー(x,y)・`level`・向き） | map JSON（新 `height.pieces`、§4） | **描画側が1回だけ適用** |
| 画像層 | PNG（world 枠×2） | 納品素材 | **画像に lift を焼き込まない**（画像は「その部品が自分の足元に立つ姿」） |

二重 lift の防止規則:
- R1 lift を適用してよいのは**配置関数ただ1か所**（`visual_y = logical_foot_y − lift(level)`）。PNG・map データ・個別 CSS では適用しない。
- R2 `visuals`（絶対座標・lift 焼き込み済み・DEV 仮描画）と `pieces`（論理座標・描画側が lift）を**同じ id で併用しない**。lint（`lint_height_spec.py`）で重複 id と二重指定を失敗にする案。
- R3 階段・坂の「昇り」は**画像内に描く**（画像は 低い側 level の足元に登録、描画側が適用する lift は低い側 level 分のみ）。connector 内の補間 lift は**キャラ専用**で、部品には適用しない。
- R4 論理足元（blocker・walk）は素材の見た目で変えない。見た目が論理とずれる場合は画像側を直す。

アンカーの登録（world 枠の下中央）:
- 標準: アンカー = world 枠の下辺中央 = 部品の論理足元。自動 crop でアンカーを動かさない（透明余白を保持）。
- 高台の縁（`height_plateau_edge_01`）: アンカー = 上段（高い側）の縁の足元、`level` = 高い側、描画側が +56 の持ち上げ（= −56 の見た目）を適用。
- 崖面（`height_cliff_*`）: アンカー = **低地側の壁の足元**、`level` = 低い側（0）。画像は足元から上へ 56 world px（@2x で 112px）の壁面。天端は上辺で高台の縁に接続。
- 前景の樹冠: アンカー = 木の接地位置（足元 y=470）、葉の下端は足元の 30 world px 上（枠の下 30 は透明）。level の lift を受けない地面木（level 0）。

## 4. 登録方式（承認済み設計。コードは未着手）
【提案】`height.pieces: [{ id, asset, anchor:[x,y], level, dir?, z?, fade? }]`。`asset` は `height_*`（manifest の `node`/新 `height` ルール、`w`/`h` は world px、bottom-center）。描画は既存のプロップ描画と同じ DOM（img）で、`lift` を位置に反映。実装は Phase 2 後工程で、まず DEV マップで検証する（本編マップは有効化しない）。

z（描画順）の規則（【事実】DEV の値から読み取れる現行規則を明文化）:
- 立体物（崖面・欄干・橋脚・樹冠）: z = **論理足元 y**（キャラと y ソート）。例: `cliff_face z=420`、`rail_w_480 z=560`（区間南端 480+80）、`pier z=960`、`tree_canopy z=470`。
- 床類（橋床・高台の床・階段/坂の踏面）: **overpass/connector ごとの固定 z を全タイルが共有**（橋床 z=440）。キャラは床より常に上（`y+…>440`）。橋の下の level-0 キャラは `overpass.z−1`。タイルごとに別 z にしない（奥のタイルがキャラの上に出る）。
- 橋の `fade:'deck'` グループ（床・欄干）は橋の下にいる間 `.42`。橋脚は fade 対象外。

## 5. 階段・坂の4方向仕様（D1・D2・D3 反映）
【事実】DEV 実装: `stairs_plateau` rect 120×120 axis y fromEnd max（南が低い・北へ昇る）、`slope_plateau_w` rect 120×100 axis x fromEnd min（西が低い・東へ昇る）、橋の進入 `ramp_bridge_n/s` 120×120。connector の `zone`=0.22（走行方向の端 22% で level が切り替わる）。
共通ルール: 昇り方向 = 高い側へ進む方向。画像名の `{n,e,s,w}` は昇り方向。アンカー = 枠の下辺中央 = 足元矩形の**南端中央**。方向で空く部分は透明。階段の昇り・坂の昇りは画像内に描く（R3）。

### 5.1 階段（6段基準、D2）
足元 120×120、段差 56、枠 120×176（PNG 240×352）、4方向共通枠。6段 = 1段あたり立上り約 9.3 world px、踏面 20 world px（走行 120）。
| 方向 | 低い入口 | 高い端 | 枠内 |
|---|---|---|---|
| n | 南端 | 北端 | 北の踊り場が上辺に接する |
| s | 北端 | 南端 | 手前が高く、立上り面が下辺まで見える。上部は透明 |
| e | 西端 | 東端 | 東が高く上辺に接する |
| w | 東端 | 西端 | 西が高く上辺に接する。左上光のまま描き直す（東向きの反転にしない） |
側壁（D3）は階段本体に含めず別部品（§11 候補）。**本体の画像は側面を描かない**（側壁が別に付く／付かない両方で成立するよう、踏面と立上りの端まで本体を描く）。

### 5.2 坂（走行 120 統一、D1）
走行（昇り方向の長さ）= **4方向とも 120 world px**。断面の幅（昇り方向と直交）は、現行 DEV の `slope_plateau_w`（走行 120 × 幅 100）を変えない。
| 方向 | 走行 | 幅 | 足元矩形 (w×d) | 枠（world / PNG@2x） |
|---|---|---|---|---|
| e / w | x 方向 120 | 100（y） | 120×100 | 120×156 / 240×312（現行どおり） |
| n / s | y 方向 120 | 120（x） | 120×120 | **120×176 / 240×352（従来案 120×156 から変更）** |
勾配はどの方向も 56/120。

**D1 の影響と矛盾（実装前に作者確認が必要）**
- 素材依頼書（`height_asset_requests.md`）の坂は「4方向共通の 120×156 枠、足元 120×100」とあり、n/s では走行が 100 のため **D1 と矛盾**する。本書の方針では n/s の足元が 120×120、枠が 120×176（階段と同じ）になる。依頼書の坂 n/s（#7・#9）の枠・プロンプトを修正する。
- 幅が方向で異なる（n/s=120、e/w=100）。歩行幅の差が気になる場合は、e/w の幅も 120 にそろえる案があるが、これは現行 DEV の `slope_plateau_w`（高さ別 walk・blocker・connector 矩形）の変更になり Phase 1 の DEV データに触れるため**採用しない（作者が望む場合のみ別途）**。
- connector: n/s の坂は rect 120×120（axis y）、zone=0.22 → 走行 26.4 world px。e/w は現行どおり。lint の「connector 両端の 22×10 足元が walk に支えられる」は幅 100/120 とも満たす見込み（DEV で確認）。
- アンカー（南端中央）は不変。枠高が 156→176 になるのは n/s のみ。z は connector の固定 z（§4）。

D2 の検証事項: キャラの lift は連続補間（`progress`）、階段の絵は離散 6 段。最大の見かけのずれは約 ±4.7 world px（半段）。DEV で足元が段に刺さって見えないかを確認（§12）。`zone`=0.22（26.4px ≒ 1.3 段分）と段の位置がずれて見えないかも確認。

## 6. 橋（床・欄干・端柱・橋脚）の接続仕様（D4・D5 反映）
【事実】DEV: 床 walk 120×640（level 1）、床 visual は 120×80 ×8 相当（visual y=424）、欄干は西 x=1500/東 x=1610・幅 10・区間 80（visual 高さ 102）、橋脚は論理 16×20（level 0 blocker）で visual 16×76。進入は両端の `ramp_bridge_n/s`（120×120 connector）。
- 床タイル `height_bridge_deck_tile_01`: 120×80、奥行方向 80 周期、上下辺は不透明で連結。level 1、論理 120×640 を 8 枚。z は橋全体で固定（`overpass.z`）。
- 欄干 `height_bridge_rail_{w,e}_01`: 10×102、区間 80、アンカー = 区間南端の足元、level 1。**支柱を持たない**（D4）。上下の連結辺で手すり・横木がそのままつながる（反復して支柱が重複しない）。
- 端柱（独立部品）: 橋の北端・南端・必要な途中位置に別配置（§11 候補）。欄干の連結継ぎ目と端柱の位置は `pieces` の座標で決める。

D5 の検証事項: 橋の下を歩く level 0 のキャラに対し、橋脚がキャラより手前/奥に正しく描かれること（z=柱底 y）、床・欄干が半透明（.42）になる一方、橋脚だけ不透明で見え方が不自然でないこと。

## 12. DEV マップで検証する項目と合格基準（Phase 2 実装後）
| # | 項目 | 合格基準 |
|---|---|---|

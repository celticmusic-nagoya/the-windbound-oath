## 参照ルール
1. **優先順位**: ユーザーの後日の明示採用 ＞ **正式追補（`CANON_ADDENDUM.md`）** ＞ v5.0 の最新追補 ＞ v5.0 のそれ以外 ＞ 旧版アーカイブ（履歴参照のみ）＞ 企画案・仮案。原本（v5.0）だけを読んで済ませない。
2. **ラベルの区別**: 確定／脚本採用案／未決定／撤回／要コード照合 を原本どおりに区別する。候補・脚本採用案・未決定を、ユーザーの承認なしに確定へ昇格しない。
3. **設定確定 ≠ 実装済み**: 実装状況は現行 main のコード・Git 履歴・テスト結果で確認する。コード上の数値を公式設定へ昇格しない。
4. **独断で変えない**: 既存のシナリオ・台詞・キャラクターデザイン・ゲームバランスを、資料だけを根拠に変更しない。
5. **読めない場合**: 推測や記憶で補完しない。**アクセス不能として報告**し、ユーザーに確認する。設定に依存する部分は現状維持にする。
6. **相違の報告**: 設定と実装に相違があれば「設定／実装／差分／推奨対応／優先度」で報告する。

## 非公開リポジトリへのアクセス方法
1. 権限: リポジトリ所有者（ユーザー）が、作業者（Claude / Codex の実行環境のアカウントやトークン）に `celticmusic-nagoya/the-windbound-oath-handoff` の読み取り権限を付与する。トークン等の認証情報は**このリポジトリに書かない**。
2. 取得（読み取りのみ、固定コミットまたはブランチを指定）:
   `gh api -H "Accept: application/vnd.github.raw" "repos/celticmusic-nagoya/the-windbound-oath-handoff/contents/reference/lore/<ファイル名>?ref=<ブランチ名またはコミットSHA>"`
3. 検証: 取得した原本を `sha256sum` で上表の SHA-256 と照合する（同ディレクトリの `SHA256SUMS`）。不一致なら使わない。
4. 取得できない場合: 推測・記憶で補完せず、報告に **`LORE_INACCESSIBLE`**（試した経路とエラー）と書き、設定に依存する部分は現状維持にする。

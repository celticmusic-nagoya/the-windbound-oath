- 判定はすべて 2D 画面上の代理指標であり、3D 接触や形状を証明しない。

## 1. 結論

F06 の失敗原因は2つある。

1. **計測の欠陥（遮蔽依存）＝W108/W118 の直接原因**：旧判定は「今見えている緑色ワイヤー画素」までの距離を測っている。描画済みの毛束がガイドを覆い隠すと、ガイドが動いていなくても判定が悪化する。W108 の6段階で、ガイド形状は不変（一致率 1.000）なのに、見えるワイヤーは 1795→1202 px（−33%）に減った。
2. **設計とガイドの余裕不足（品質・再現性リスク）**：遮蔽のないきれいなガイド面で測っても、F06 はガイド外縁から最大 +4.5 px（経路の 79%）、F01 は +5.7 px（81%）外側にある。旧判定は「ワイヤーから 5 px 以内」を許していた。

実測した結果：

- W108 の F01 は、ガイド外 5〜6 px に入る地点（31 点中 19 点目）で**描画が途切れており、設計長の約 61%** しかない。
- W120（run 46150846797、隔離 asset 804739416）の F06 は、ガイド外 +4.3 px の経路のまま**全長が描画された（完了率 1.00）**。私は事前に「途中で切れる」と予測したが、これは外れた。この倍率では、エディタがガイド外 4.5 px 程度までは投影し、5 px を超えると途切れる、という境界が観測された（2点からの推定であり、確定値ではない）。
- W120 の停止は保存段階で起きた。`Save as new item` のボタンは押下状態まで遷移したが、固定待機 4 秒の時点でダイアログが残っていた（§7）。ガイドの問題ではない。

## 3. W120 の実結果と次回への反映（現行の所有者・方式は変更しない）

- 隔離 visibility 方式は `ISOLATED_GUIDE_FIT_PASS` となり、F06 stroke の送信と `Hair 6` の新規ラベル作成まで成功した。新しい audit では F06 が COMPLETE 1.00（上着領域の差 0）だった。
- 停止箇所は保存ダイアログである。前後の画面差は最大 186 で、ボタンは押下表示まで変化したが、`sleep 4` の後もダイアログが残っていた。保存処理の待ち時間不足、または押下が確定しなかった可能性がある（どちらかは未確定）。盲目的な再クリックは「新規アイテムの二重作成」のおそれがあるため、ダイアログが消えるまで画面を状態ポーリングし（例：最大 20 秒・1 秒間隔）、それでも残る場合だけ Custom タブのアイテム数で状態を確認してから判断する方式を推奨する。
- 次回は、F06 と同じ stroke 経路を再利用する場合でも、各 stroke 後に `stroke_completion_audit.py` を実行する。保存の前に COMPLETE を確認しておくこと。
- 重要な運用上の注意：W117 以降の試行は、開始時と最終保全時に #427 ブランチ HEAD = `df986c7e` を確認している。**試行中に #427 へ push すると、成功した結果も隔離扱いになる。** そのため今回は #427 ブランチへの push を避け、別ブランチに置いてコメントで共有した。今後の独立分析も同じ扱いにするか、HEAD の固定を owner 宣言だけに限定することを推奨する。

## 4. 新方式：独立した新規ガイドによる前髪・横髪・頭頂の制作

既存の Freehand Group 1 のガイドを変形すると、描画済みの 5 本も一緒に変形するおそれがある（VRoid の毛束はガイド面に従属する。実機で要確認）。そこで既存グループには触れず、**部位ごとに新規 Freehand グループと新規ガイドを追加する**。

| グループ | 対象レーン | 新ガイドの目標包絡（W108 画面 px、1.28 倍） | 必要拡張量 |
|---|---|---|---|
| G1（既存・維持） | F03 / F04 / F05（F02 は HOLD） | 現状 | — |
| G2 前髪外側 | F01（作り直し）、F06（W120 で描画できたのは境界ぎりぎりのため、余裕のある再描画を推奨） | x473〜547、y317〜379 | 左 7.7 px、右 6.5 px |
| G3 左横 | SL01〜03 | x446〜504、y308〜437 | 外側 33.6 px |
| G4 右横 | SR01〜03 | x520〜576、y309〜437 | 外側 31.1 px |
| G5 頭頂 | C01〜C06（W113 設計） | 頭頂の殻を 3/4 視点で計測 | 実測待ち |

包絡の設計図座標（W92 座標系）は receipt の `target_bounds_blueprint_px` に出力した。

手順は次のとおり。

1. 隔離した作業コピーで `Add Freehand Hair Guides` を実行し、新規グループを作る（G1 は選択も変形もしない）。
2. 新規ガイド単体（他の毛束を描く前）を正面と 3/4 で撮影し、`guide_support_v2.py` の参照ワイヤーにする。この 1 枚がそのグループの「きれいなガイド」となり、以後の遮蔽に影響されない。
3. `guide_envelope_plan.py` で、対象レーンが r+u≦−1 px を満たすまで制御点を調整する（1 回動かすごとに再計測し、悪化したら戻す）。
4. 描画は外側から内側へ進め、各 stroke 後に `stroke_completion_audit.py` を実行する（COMPLETE でなければ undo）。
5. G1 の F01 は G2 の F01 が COMPLETE になってから非表示にして比較し、削除するかどうかは別途判断する（今回は削除を提案するだけ）。

## 5. 前髪専用材質の分離

W112 の解析では、新しい Front グループと旧 Back 18 グループ／59 本が同じ global material を参照している。W111 の素材を直接 import すると後ろ髪も変わる。

手順（2.16.0 実画面の `Materials … + ⧉` を確認済み。操作の効果は未検証）：

1. 隔離コピーの Front エディタで、既存の `Material` を複製する（⧉）。新規作成（+）より、現在のパラメータを引き継げる複製のほうが比較しやすい。
2. 複製した材質を新規 Front グループ（G1、および §4 の新グループ）に割り当てる。割当 UI はグループ行の色見本などが候補だが未確認のため、まず非破壊の調査として実画面で確認する。
3. 複製した材質にだけ W111 の Main / Highlights（SHA `37d9ebee…` / `f97f065e…`）を import する。
4. 受入条件は W119 の candidate guard を再利用する：94 個の保護 record、Back 18 グループ／59 本、旧 global material の各 fingerprint が不変で、Front グループの material 参照だけが新しい材質に変わっていること。保存→再読込でも同じであること。

## 6. 頭頂部を含む髪全体の品質向上

- 前髪の根元は全レーンで y≈321〜322 に集中しており、ガイド上端（y315）との間と頭頂の帽子状領域が露出している（W110 の実画像 proxy でも、y30〜50 帯の紫被覆率は正式図 99% に対し W108 は 17%）。G5 頭頂グループで根元帯を覆い、前髪の根元はその下に潜らせる。
- 前髪が 5〜6 本しかない場合、束が太い刃状に見える（W108 G2 所見）。外側の束を G2 に分けて細く・薄く描き、G1 の中央束との間に細い補助束（flyaway FL01/FR01 の幅 2〜3 設計値）を追加する。
- 横髪と後ろ髪は旧プリセット由来の灰色輪郭が残っている。G3/G4/G5 が完成したら、旧 Back の扱い（非表示で比較してから判断）を別工程で決める。
- 頭身 6.25 の再計測（髪を除く解剖学的な頭頂）と、頭頂ボリュームの評価は分ける（髪の量で頭を大きく見せない）。

## 7. GUI 自動操作の安定性と連続制作効率

| 課題（実測） | 改善 |
|---|---|
| 全身表示でガイドが 61×109 px しかない（許容 5 px ≒ 幅の 8%） | 頭部を拡大した精密フレーム（w107 register の scale 上限 3.8 の範囲、例 2.5〜3 倍）で描画する。px 単位の量子化誤差が約 1/3 になる |
| 固定 sleep が計 38 秒・18 箇所。W120 は保存ダイアログ後の `sleep 4` で失敗した | 画面署名（OCR ラベル＋差分ゼロの連続 2 フレーム）を待つ状態待ちに置き換える。上限時間は残す。保存のように副作用のある操作は再クリックせず、事後の状態で判定する |
| 固定座標クリック 5 箇所（例：Hair 4 の目アイコン 0.2695, 0.6185） | 行ロケータ（W34）でラベル基準の相対座標を求め、行数が変わっても同じ行を押す |
| 遮蔽で判定が悪化する | `guide_support_v2`：ガイドは一度だけきれいに撮影し、以後は登録変換で写像する。非表示操作が不要になり、目アイコンの誤操作リスクも消える |
| 途中で切れた毛束を検出できない | 各 stroke 後に `stroke_completion_audit` を実行し、TRUNCATED なら即 undo |
| 1 回の起動で 1 本（F06）だけ | 1 回の起動で、グループ作成→ガイド撮影→複数レーン描画→監査→保存・再読込をまとめて行い、全工程にチェックポイントを残す |

## 8. 同梱ツール

| ファイル | 内容 |
|---|---|
| `guide_support_v2.py` | 遮蔽不変のガイド支持判定（ガイド形状の不変性を検査し、ガイド面への符号付き距離と r/u/t で判定。旧 Chebyshev 指標も併記） |
| `stroke_completion_audit.py` | stroke 前後の画面から、設計経路の実描画率を測定（COMPLETE / TRUNCATED / NOT_DRAWN / ROOT_GAP / HOLD_FRAME_DRIFT） |
| `guide_envelope_plan.py` | 既存ガイドで描けるレーンの判定と、新規ガイドに必要な包絡・帯ごとの拡張量の算出 |
| `test_w121a_guide_analysis.py` | 合成データによる正負対照試験 5/5（認証情報・非公開データ不要） |
| `W121A_REAL_DATA_RECEIPT.json` | 実データの数値結果と入力 SHA |

実行例：`python3 tools/morwen_hair_analysis/test_w121a_guide_analysis.py`（Python 3.13、numpy 2.5.3、scipy 1.18.1、Pillow 12.3.0 で確認）。

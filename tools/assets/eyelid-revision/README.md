#20E approved eyelid-shape asset build

User requested Fiona/Lou eyelid correction for both blinking and expressions, then approved `docs/portraits/review/eyelid-shape-reference-20261030.png`. Emma was declared Android QA PASS and is excluded.

Creative eyelid edits were made with imagegen from each adopted normal and the approved shape reference. `source/*_closed_donor.png` are **NOT game portraits**: they may contain unrelated generated differences, and must never be registered as normal replacements. Both have exactly the source canvas dimensions; explicit donor→normal translation `[0,0]`, no implicit resize. Only the bounded smooth per-eye masks are composited into runtime assets.

Run `python3 tools/assets/eyelid-revision/build.py` with Playwright/Chromium available. JavaScript performs the native offline compositor, moving original lash texture toward the approved closed-eye curve for intermediate frames, then using the donor closed eye at frame4. Python transports rawRGBA and losslessly encodes PNG; it never modifies pixel arrays. RawRGBA transport avoids canvas premultiplication rounding changing alpha254 source pixels outside the eye masks. Each static expression starts with its previous20C expression, preserving every alpha byte and every pixel outside the eye masks; original mouth/brows/body remain. Masks are exported for a separate integrity test.

Runtime: same `PortraitRegistry` / `TalkPortrait` / `PortraitBlink`, unchanged260ms timing and3–6s gaps. Fiona/Lou versioned assets under `provisional-20e/`; all20C PNGs retained. Normal PNGs are never build outputs. Expression states are explicit in JSON: Fiona smile/relieved use gently closed eyes, angry narrower than determined, sad/worried soft partial lids; Lou keeps only its authorized five expression differences. Surprised remains open-eyed; Lou's already-correct surprised pixels may stay identical. All derived files remain PROVISIONAL_ANDROID_QA until final asset adoption is explicit.

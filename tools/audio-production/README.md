## Read-only loudness and producer-to-Studio qualification
`python tools/audio-production/inspect_audio.py pair source.wav candidate.wav receipt.json inspection.json` verifies both v1 audio hashes and PCM measures, then records FFmpeg loudnorm INPUT integrated LUFS, true peak (dBTP), LRA and gating threshold; output of the filter goes to null, not to an audio file. Measurement receipts are separate and refuse overwrite. Provisional -1 dBTP headroom is only a technical diagnostic (HOLD above); no universal LUFS target or loudness normalization, listening, loop or game approval. LRA from very short fixtures is not a production music dynamics assessment. ## Delivery candidates
`python tools/audio-production/export_delivery.py export candidate.wav <sha256> output --role loop` (or `--role oneshot`) generates Ogg Opus and MP3 candidates, with source and output SHA, encode settings, actual decoded frames/channels/LUFS/true peak and byte ratios. Source must be PCM16 48 kHz <=120 s with sample headroom. Loop sources must pass provisional endpoint jump and slope-difference limits 0.025 full-scale; this is a technical diagnostic, not proof of a musically seamless loop. Ogg Opus loop requires exact decoded frames; MP3 is one-shot fallback, never loop-certified here. One-shot allows 20 ms frame difference; both require true peak <=-1 dBTP and integrated LUFS difference <=1. These are provisional candidate QA limits, not formal game standards. Chromium qualification decodes actual compressed bytes at 48 kHz, renders two loop cycles and checks exact repeat, endpoint discontinuity and actual playback. No real device, game integration, listening, or adoption. Synthetic fixtures only; no paid dependencies or new public game assets.
